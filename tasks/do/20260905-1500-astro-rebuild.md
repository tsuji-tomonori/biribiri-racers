# 1人用レーシングゲームのAstro再構築

状態: do
タスク種別: 機能追加

## 背景・目的
旧実装のUI/操作品質不足を解消し、1人で遊べるゲームをGitHub Pagesへ公開する。旧アプリの置換・公開はユーザーが明示的に許可。AGENTS/skillsの作業ルールは保持する。

## 範囲・計画
- 旧app実装をAstro＋strict TypeScriptのroot projectへ置換。
- 添付5コースと直前に作成したオリジナルマシンを使用。
- 自動加速、押してチャージ・離してダッシュ、壁接触でスタート、順路通過後のゴール、CPU3台、練習。
- ユニットテスト、Playwright E2E、Pages向けCI/CD。
- PR・マージ・公開URLの動作確認まで実施。

## 文書整備
旧製品文書は今回の範囲に置換し、README、UI仕様、アーキテクチャ、運用、原子的要件を更新する。作業報告をreports/workingに記録。

## 受け入れ条件
- [ ] Astro静的ビルド、TypeScript strict、型検査成功。
- [ ] 5コースでCPUとプレイヤーが合法的に完走可能。
- [ ] スタート/ゴール往復・逆走・順路省略では勝利しない。
- [ ] 衝突でスタートと進行度をリセットする。
- [ ] 開始・操作・ポーズ・復帰・リザルト・リトライ・画像失敗のE2Eが成功。
- [ ] 375/768/1440pxにて操作部品の可視性・横溢れを検証。
- [ ] CIに型検査・テスト・E2E・ビルド、成功後のPagesデプロイと公開後smokeを設定。
- [ ] mainに反映しGitHub Pages公開URLを開いて動作を確認。

## 検証計画
npm run check / npm test / npm run build / npm run test:e2e。公開後Playwright smokeとブラウザーによる実画面確認。外部通信不要・秘密情報不要。

## UI仕様・アセット対応
参照: project_sourcesの03/06/16（1672x941）と04/07/08/14/15（1254x1254）。
メニュー: 左に操作・開始、右に実際のコース・5つの選択カード。青＋白＋ピンク、強い輪郭、丸いボタン。
レース: コースが主画面、上に実時間と操作、左に順位、右にミニマップ、下に速度・チャージ・タッチ操作。ロード/エラー/カウントダウン/走行/停止/結果を明示。
デスクトップ1440pxは2カラム、モバイル375pxは縦配置。主操作44px以上。Spaceなどの操作キーは選択フォームでは奪わない。モーダルはフォーカスを閉じ込め、閉じると起点へ戻す。
コース画像: 前ターンで提供画像から変換したcourse-0..4.webp（画像そのものを表示、当たり判定は同一座標）。マシン: 同ターン生成のracers.webp。アイコン: ネイティブ文字ラベルを優先。未実装オンライン部品は作らない。
推定: 原画の画像内UIをピクセルコピーすることは今回の目標ではなく、ゲーム体験と視覚階層を維持してレスポンシブ化する。精密な一致は主張しない。

## レビュー観点・リスク
ゲームエンジンとDOMを分離、テスト専用機能を本番に出さない、base path、公開後ビルド識別、古いDocsとの矛盾、当たり判定と画像のずれ、タッチキャンセル、フォーカス離脱時の停止。実機パッド/スクリーンリーダーの確認ができない場合は明記。
