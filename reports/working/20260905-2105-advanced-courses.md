# 中上級ギミックコース追加レポート

## 受けた指示・要件
長く複雑な中上級コースを2〜3個追加し、風・バナナ型スピン・加速床を組み込む。

## 実施内容・判断
- 新3コースを追加し全8コース化。スカイストームは約10,511、バナナジャングルは約16,352、ボルトファクトリーは約13,662座標単位。既存最長4,683の約2.2〜3.5倍。
- 青機体・アシストON・プレイヤー速度の自動操縦で約70/111/98秒。既存約22〜44秒より長い。人のプレイ時間の保証値ではない。
- 風は85単位/秒、スピン0.8秒停止＋一回転、加速床1.1秒・1.55倍。機体ごとに退出後再発火。PUSHで加速解除。復帰・停止・再開始へ対応。
- 既存画像5枚と機体は維持。新道路を共通の壁ポリゴンからSVGで描き、追従・全体・ミニマップを2800/3200四方に拡張。
- 補間点の間隔が不均等だと長い直線の入口で経路が逆行するため20単位以下に再標本化。全機体の完走で確認。
- やさしいCPUの所要時間に合わせ、新コース対戦上限は300秒。既存180秒と練習無制限を維持。
- README、UI設計、アーキテクチャ座標、既存コース数を参照する要求を同期。

### 検証コマンド補足
ローカルE2Eは`NO_PROXY=127.0.0.1,localhost npx playwright test --config=/tmp/biribiri-playwright.config.mjs`を使用。作業用設定は既存設定を継承し、Chromium 149の実行パスと静的配信サーバーのみ変更（最後のリプレイでは動画記録OFF）。全体実行の後、`--grep '新コース|読み込み・開始'`、`--project=chromium --grep 'キー操作だけ'`相当の対象再実行で修正を検証。CIには通常の`npm run test:e2e`を維持。通常ブラウザ取得失敗とプレビュー起動失敗を隠さず、実際に成功した構成を記載している。
