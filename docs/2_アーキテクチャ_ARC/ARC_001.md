# ARC-001 ゲーム構造

種別: アーキテクチャ / 状態: 実装済み

Astroが静的UIを生成し、TypeScriptモジュールが起動する。`tracks`の座標を`geometry`が経路・順路ゲートに変換し、`physics`が各機体を1/120秒刻みで更新する。`Session`は状態・カウントダウン・順位・終了を管理する。Canvas描画、音、DOMは物理から分離する。

通常遷移: menu → countdown → racing → finishing → finished。countdown/racingはpausedから元の状態へ戻る。リトライは新しいSessionを作成する。画面離脱・非表示では時間と入力を停止する。レースは最初の完走または180秒で終了、練習は単独完走まで走れる。

衝突は半径30の円とポリゴン各辺の最短距離で検査する。内壁には厚み18と画像ごとの壁立ち上がり補正（通常15、氷0）を加える。接触で速度・進捗・チャージを消し、最後の合法位置で0.3秒停止後に初期位置へ転送、0.75秒待機する。ゴールには3つの共通区間の正方向通過、最低走行距離、内側の通行不能な島の周りの符号付き回転角が2π以上、スタート線への正方向帰還が必要。開始/終端の経路重複は通過区間数で探索対象を分ける。CPUも同じ衝突・チャージ・ゴール判定を使用する。高速な描画と更新頻度を分離し、単フレーム上限0.25秒で復帰時の飛び越しを防ぐ。

画像の座標と当たり判定はコースごとに共通（既存1254四方、新3コース2800/3200四方）。コース変更で勝手に別画像を出さない。画像取得失敗は明示し開始を禁止する。外部API、個人情報、認証、ランキングサーバーはない。配信は意図的に公開する非機微のゲームデータだけ。管理権限はGitHub Actionsのdeploy jobに限定する。

`machines.ts`を選択表示と物理の単一設定源とし、CPUも同じ特性で更新する。チェック区間は`tracks.ts`で明示し、分岐内のCPUセンターラインとは独立する。図は既存の短い状態遷移記述で十分なため省略する。
