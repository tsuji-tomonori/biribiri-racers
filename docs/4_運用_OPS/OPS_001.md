# OPS-001 検証・Pages公開

種別: 運用 / 状態: 実装済み

Node.js 24で`npm ci`。READMEのcheck・format:check・test:coverage・build・test:e2eを順に実施する。ローカルE2Eはpreview serverを起動し`/biribiri-racers/`を検証する。PLAYWRIGHT_BASE_URLを指定すると公開URLを対象にする。

GitHub Settings → Pages → SourceをGitHub Actionsに設定する。workflowはPRとmain pushで検証を実施。mainだけが検証済みdistをuploadし、pages:write / id-token:write付きdeploy jobで配信する。PRからは公開・書込をしない。npm lockで依存関係を固定、E2Eには外部APIも秘密情報も不要。

公開後smokeはmeta build-revisionとGITHUB_SHAが一致するまで最大60秒待ち、開始・自動走行・停止・復帰・リトライ・コース選択への復帰を本番URLで操作する。不一致や操作失敗はCI失敗とする。テスト失敗時のtrace/video/screenshot、各画面幅の画像、カバレッジをActions artifactsに14日間保存。

失敗時: verify失敗なら既存公開版を維持しログ・traceから修正。deploy失敗ならPages設定とenvironmentの許可を確認。smoke失敗なら公開版に問題がある可能性があるため成功扱いしない。必要に応じて最後に正常だったコミットをrevertで復元して再検証・公開する。force pushや手作業のdistアップロードを復旧手順にしない。

この公開ページに管理API・個人情報・ログインはない。ブラウザ内でのみ実行するため永続サーバーの所有者境界やレート制限は対象外。ブラウザ改変によるローカル結果の変更は他人へ影響しない。

画像URLにはビルドSHAを付与する。同じファイル名で画像を更新しても、既存ブラウザが旧画像キャッシュを流用しないようにする。
